надо реализовать html5-игру, суть такова

игровое поле, 5на5 клеток, игрок - курсор, выделенная клетка по центру *(это то откуда стартует игрок)*

задача игрока: выучить наизусть мутации игрового поля чтобы оптимальным способом заработать за меньшее число действий требуемое число очков

доступные действия игрка: перемещение курсора по игроковму полю вверх, вниз, влево и вправо по стрелочкам на клавиатуре

И потребление клетки на пробел. Потребление клетки добавляет к текущему числу очков игрока кол-во очков равное содержимому клетки и очищает клетку

условие победы: пользователь набрал максимальное число очков за меньшее число ходов,
условие паражения: игрок потратил больше ходов чем требовалось и не смог набрать нужное число очков.
при поражении игра перезапускается но (*важно*) последовательность мутаций не меняется, чтобы игрок мог изучить всю последовательность повторно.

при старте игры игра генерирует случайное кол-во мутаций и пробелов между ними + начальное рассположение клеток.
мутации могут быть (каждой мутации соответствует её иконка):
1. 🔢 - добавление на игровое поле 4х клеток с очками (от 1 до 5) в выбранных детерменированных позициях (при повторном ретрае игры клетки должны получить очки в тех же позициях что и в предыдущем трае - при старте игры игра выбирает разброс и значения случайно но мутация остаётся фиксированной до тех пор пока игрок не выиграет эту мини игру. если во время добавления клетка была непустой - она затирается)
2. ▶/◀/🔼/🔽 - сдвиг всех клеток на поле на 1 клетку вправо, влево, вниз или вверх (если клетка находится на границе, - её не двигаем)
3. ➕ - увеличение каждого значения каждой непустой клетки на 1
4. ➖ - уменьшение каждого значения каждой непустой клетки кроме 1 на 1
5. ↩ - поворот игрового поля по часовой стрелки на 90 градусов
6. ↪ - поворот игрового поля против часовой стрелки на 90 градусов

пробел - пустая мутация которая ничего не делает, ⚫

при старте мини игры игра генерирует и (самое важное:) фиксирует в памяти случайный набор указанных мутаций, а также сразу применяет первую мутацию (которая должна быть типа 1 - добавление новых непустых клеток)

последовательность обязательно должна быть разделена пробелами. пример генерации:

🔢⚫⚫🔼⚫➕⚫⚫⚫↪⚫🔢⚫⚫➕⚫⚫⚫⚫⚫...

как видно, чтобы не забивать память, начиная с какого-то места сгенерированная последовательность должна содержать только пробелы, а между каждой мутацией которая производит эффект есть как минимум 1 пробел.

после этого игра анализирует сгенерированную последовательность и, зная полностью все что будет просходить с игровым полем, выбирает какую-то цель (скажем, набрать 10 очков) и считает минимальное число действий необходимых для достижения этой цели

после этого начинается сама игра, которая происходит последовательно по шагам. Ждём ввода от пользователя (выбор действия) и после выбора действия сразу производим его после чего

смещаемся в последовательности на 1 вправо и производим мутацию (если она была в генерации) или не производим (если пробел). повторно ожидаем действия пользователя.

чтобы игроку было понятно примерно что будет происходить с полем внизу поля показываем ближайшие 3 позиции последовательности в виде эмодзи указанных выше.

к примеру, если в нашем приммере генарции выше первая мутация должна добавить 4клетки в позициях [0,1]=2,[3,4]=3,[0,4]=5,[4,0]=3 то при старте игры игровое поле будет выглядеть примерно так

| |2| | |5|
| | | | | |
| | | | | |
| | | | |3|
|3| | | | |

курсор игрока находится по центру (визуально это можно отобразить выделением ячейки), внизу отображаем ближайшую последовательность мутаций в нашем примере это ⚫⚫🔼

при любом действии игрока мы сначала производим само действие, после чего применяем элемент сгенерированной последовательности и смещаем строку мутаций (игроку всегда видно 3 ближайшие мутации)

например первым ходом игрока стало движение влево , я отображу состояние игрового поля показав где игрок в виде иконки 👤 но в самой игре курсор игрока отображён выделением клетки

| |2| | |5|
| | | | | |
| |👤| | | |
| | | | |3|
|3| | | | |

мутация-пробел ничего не меняет поэтому под игровым полем мы показываем ⚫🔼⚫

и т.д.

таким образом игрок совершает действия и постепенно набирает очки, если происходит такое что требуемое (выбранное игрой) число очков не набрано а игрок уже превысил лимит действий - сбрасываем всю игру,

возвращаем игрока в начальную позицию, очищаем игровое поле, перезапускаем (важно:) ТУ ЖЕ последовательность мутаций и применяем первую мутацию, после чего даём управление игроку.

игрок победит как только наберёт нужное число очков за выбранное кол-во действий, после чего происходит победа в игре и мы показываем кнопку "НОВАЯ ИГРА", эта кнопка делает всё то же самое что я описал выше за исключением того
что последовательность мутаций, цель и кол-во доступных действий генерируются новые (в последовательности мутаций самая первая мутация это всегда 🔢).

# как это выглядит с точки зрения игрока

при старте игры поле заполняется случайными клетками но если игрок проигрывает то он начинает с центра и клетки будут такими же,

после каждого движения или потребления клетки происходит какая-то мутация с игровым полем, если пробел- ничего не происходит, список ближайших мутаций я всегда могу посмотреть под полем, и он детерменирован в том плане,
что если я проиграю то вся последовательность мутаций начнётся с начала.

компьютер за меня генерирует условия и выбирает цель - число очков, я выиграю если двигаясь и потребляя клетки получу в сумме указанное число очков за меньшее число действий. потребление клетки тоже считается дейтствием.

# корооткий пример всей игры

игра начинается и мы генерируем случайную последовательность мутаций, после чего фиксируем последовательность - она не будет меняться до тех пор пока игрок не выиграет игру

🔢⚫⚫🔼⚫➕⚫⚫⚫↪⚫➕⚫⚫➕⚫⚫⚫⚫⚫...

для простоты подсчёта я выбрал недлинную последовательность и мутаций заполнения 🔢 всего одна, в первичой мутации данные для заполнения такие же как в примерах выше [0,1]=2,[3,4]=3,[0,4]=5,[4,0]=3

на основе полной последовательности мутаций которую мы знаем а игрок пока нет, выбираем цель - 10 очков, проанализировав последовательность и потенциальные шаги игрока приходим к выводу что такое число очков можно набрать за минимум 10 шагов, - больше игроку не надо.
